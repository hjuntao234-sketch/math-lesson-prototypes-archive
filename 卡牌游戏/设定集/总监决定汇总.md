## 三、给谁玩

“让好学生和后进生都满意是不太可能的，后进生应该在简单题那块有你前面做的剧情拓展，至于难题，等他们变成好学生之后接触自然会懂，否则不建议他们接触。后进生能看懂难题，本来就是逻辑悖论。”

- 难题不做托底，不为后进生降门槛。
- 后进生走简单题加剧情拓展。

## 五、学习上的判断（Claude 11-09 对用户说的，用户同意）

学生学得到“怎么选”，学不到“自己算完”和“自己想起方法”。四个硬伤，前三个已动手：

1. 面板替学生做了关键推导 → 牌长大后撤掉（已做）。
2. 手牌把候选摆面前，是认出来不是想起来 → 关灯再打（已做）。
3. 费用泄露答案 → 没走过的路不标价（已做）。
4. 纸上落笔没人查 → 还没解决。传承让老师至少看得到学生把什么当关键。

**没有真人数据。** 扩产不等于证明了有效。

## 六、传承和 API

- “把落笔给变成具有吸引力的动作”。走传承：学生留纸签，老师审，进名录，后来的人读到。流程见 `关卡/卡牌版.md`。
- **学生端绝不接 API。**“我没打算把这额度给学生用，这存在安全风险。”
- “API用来辅助审核，筛选”：只在老师这边，`v6/tools/screen_notes.py`。AI 只给建议，放不放行老师点。
- 密钥只来自环境变量或系统密钥存储，不写进项目、提示包、日志。接手的人不索取、不读取、不记录密钥。
- 学生的码、纸签别放进交接文件夹。不上传学生数据到别处；上传手写、进课堂，先问用户。
- AI 生成的素材，公开时要标注。

## 六之二、治“用名词代替思考”（2026-11-12）

- 样品已做进试玩章，规则见 `关卡/卡牌版.md` 同名一节。
- 这是世界观的正题：名录院只认名字，主角被逐是因为“看得太慢”。别把它做成附加玩法。
- 每只新守卫都要带：`凭`、`预判`（如果它是某只的变身）、至少一处“名字帮不上忙”的坑。
- 美术与设计意见稿（`handoff/claude_to_codex/NOTE-20261112-adventure-card-art-design-review.md`）是 Claude 的建议，**用户还没逐条拍板**，不要自行照做。

## 七、怎么干活（用户吃过的亏）

- 不许脚本批量生成台词。批 1 被退回就是因为“105 层的提醒全是同一句”。

- 额度：开 3 个极高档子智能体“额度烧得快”。写关卡的主线程可以高档；走查子智能体用中档或更小的模型，一个子智能体按顺序走完一批，不要每场新开一个。
- 语言规矩写进检查脚本，光写在文档里不够。
- 要先有同领域的金样本，再铺量。

- 文件一经交出不覆盖，修订新建 `-R2`。
